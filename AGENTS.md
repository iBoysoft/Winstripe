# Notes for AI assistants

## Git

- **Do not commit to `main` by default.** Create a branch, commit there and open a pull request. Commit or push to `main` only when the user says so for that change.
- Commit or push only when asked.

## Layout

| Path | Contents |
|---|---|
| `Sources/Winstripe` | The app, one module |
| `Sources/Winstripe/Collections.swift`, `AppCollections.swift` | Collections support; the provider stays disabled, see `docs/web-app-collections.md` |
| `Themes/` | Built-in themes; `Sources/Winstripe/BuiltinThemes.swift` is generated by `scripts/gen-builtin-themes.sh` |
| `Winstripe.xcodeproj` | Lists source files one by one, so add new files there as well |
| `scripts/` | Packaging and checks |
| `Tests/fixtures` | Theme fixtures for `scripts/check-themes.sh` |

## Build

```bash
swift build
```

```bash
./scripts/bundle.sh
```

```bash
xcodebuild -project Winstripe.xcodeproj -scheme Winstripe -configuration Release build
```

- `bundle.sh` builds a real macOS 11.0 target and fails on any compiler warning.
- Xcode 27 rejects the macOS 11.0 deployment target: add `MACOSX_DEPLOYMENT_TARGET=12.0` to `swift build` and `xcodebuild`.
- CI uses Xcode 16, whose Swift 6.1 is stricter and slower than newer compilers. Long expressions can time out in type checking there and still build locally; give them explicit types and split them up.
- `Package.resolved` pins are strict in `package-release.sh`. The root file and the one in `Winstripe.xcodeproj` must list the same versions.
- macOS 14 APIs sit behind `#if compiler(>=5.9)` as well as `#available`.

## Checks

- Self-tests are `--<name>-selftest` flags, listed in `Sources/Winstripe/App.swift`. For example `.build/debug/Winstripe --l10n-selftest`.
- `scripts/check-l10n.sh` and `scripts/check-themes.sh` check strings and themes. `scripts/verify-prefs-guard.sh` runs the full set and confirms the real preferences did not change.
- `.build/debug/Winstripe --snapshot-dir DIR` renders about 270 offscreen images in seconds. Comparing old and new renders with `cmp` is a cheap regression check. Add `--collections-fixture` to cover collections.

## Release

The **Release** workflow runs by hand from the Actions tab. Given a version such as `1.2.0`, it runs `scripts/package-release.sh` and attaches `Winstripe-1.2.0.zip` to a new `v1.2.0` release. The app is signed ad-hoc and not notarized, and `appcast.xml` is not updated.

## Signing

Every configuration signs ad-hoc through `Xcode/Signing.xcconfig`, so no certificate is needed. Ad-hoc builds cannot be notarized, and macOS may ask to re-grant Accessibility after each rebuild.

Ad-hoc builds leave out the Hardened Runtime: its library validation can refuse to load the ad-hoc Sparkle at launch (`different Team IDs`). `Signing.xcconfig` turns it off for the identity `-` and any real identity keeps it, so don't set `ENABLE_HARDENED_RUNTIME` in `project.pbxproj`. Sparkle ships with the flag and Xcode keeps it, so `package-release.sh` and `sign.sh` remove it from nested code when signing ad-hoc.

- **Xcode:** copy `Xcode/Signing.local.xcconfig.example` to `Xcode/Signing.local.xcconfig` (git-ignored) and set `DEVELOPMENT_TEAM`. Archive, then export with Developer ID distribution.
- **Never pick a team in Xcode's Signing & Capabilities tab.** It writes `CODE_SIGN_*` and `DEVELOPMENT_TEAM` into `project.pbxproj`, which overrides `Signing.xcconfig` and puts the team ID in the repository. Revert those lines if it happens.
- **`scripts/sign.sh` and `bundle.sh`:** set `WINSTRIPE_SIGN_IDENTITY` to a keychain identity, matched exactly or by prefix, or run `scripts/setup-signing.sh` once for a stable self-signed "Winstripe Local" identity that keeps the Accessibility grant across rebuilds. A missing default falls back to ad-hoc; a missing identity you set fails. `-` forces ad-hoc. This output cannot be notarized.

## Debug flags

Test switches: `open dist/Winstripe.app --args --show-properties` and
`--open-start-menu`; `--activate-bundle <bundleID>` activates a running app through the taskbar
handler and writes diagnostics to `/tmp/winstripe-activate.log`. `--list-windows` writes the
Accessibility window model to `/tmp/winstripe-windows.log`; `--activate-window <pid> <title-substring>`
runs the per-window activation path.
`--pin <bundleID>` / `--unpin <bundleID>` change taskbar pins after the live app starts;
`--list-buttons` reports the current pinned/running/window button order. All three write the resulting
pin list and button order to `/tmp/winstripe-pins.log` and stdout. Multiple pin/unpin flags are processed
in argument order.
`--preview <pid>` opens that app's first visible task button preview after 1.5 seconds, keeps it
open for five seconds, and logs window IDs and capture results to `/tmp/winstripe-preview.log`
and stdout. This live debug flag opens the popup even when the preview setting is off.
`--dump-menus` builds representative combined-task, per-window-task, empty-taskbar, and Start-button
menus in English and 简体中文 and prints their titles, checkmarks, and enabled states without opening
the live app.
Use `.build/release/Winstripe --snapshot-dir /tmp/rd-win11` to generate offscreen previews for all themes,
including `taskbar-win10.png`, `startmenu-win10.png`, `taskbar-win11.png`, and `startmenu-win11.png`.
Pin fixtures are `taskbar-pinned-win7.png`, `taskbar-pinned-win10.png`, and `taskbar-pinned-win95.png`,
with Calculator and Maps closed, Safari pinned and running, and Notes running.
Winstripe 8 snapshots include `taskbar-win8.png` (1000x40), `taskbar-win8-left.png` (128x800),
`startscreen-win8.png`, `startscreen-win8-apps.png`, `startscreen-win8-search.png` (search "Ca"),
all three at 1440x900, and `preview-win8-left.png`. The renderer exits when complete. Offscreen
acrylic uses an appearance-aware solid fallback because there is no desktop behind it to blur.
Vista snapshots include `taskbar-vista.png` (1000x56, including wallpaper above the 30pt bar and the

`startmenu-vista-allapps.png`. Winstripe 7 includes `taskbar-win7.png` (1000x40),

## Implementation notes

- Without Accessibility, task buttons fall back to one per app. Window IDs normally come from the private `_AXUIElementGetWindow`, loaded dynamically; if it is unavailable, Winstripe matches process, frame and title against layer-0 `CGWindowListCopyWindowInfo` entries, which can be ambiguous for identical windows.
- Live thumbnails use ScreenCaptureKit's screenshot API on macOS 14+. macOS 13 uses title-only previews because its SDK obsoletes `CGWindowListCreateImage`.
- Pins are stored in `UserDefaults` under `pinnedApps` and `startPins` as ordered optional bundle ID and path arrays. Running-app drag order is saved by bundle ID under `taskOrder`.
- Settings persist in `UserDefaults` under `com.iboysoft.winstripe`. Offscreen fixtures and self-tests use isolated preferences.
